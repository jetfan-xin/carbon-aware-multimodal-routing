# 长江走廊与长三角设施级港口网络

## 1. 本次更新解决什么问题

历史工作簿把重庆至上海沿线地点作为城市节点，并为大部分城市对记录公路、铁路和水路距离。这适合当时的路线搜索原型，但不能证明每个城市都有对应货站、码头、班列、班轮或换装能力。

当前更新将三类事实严格分开：

1. **规划和枢纽资格**：用于产生候选节点，不能自动产生运输边；
2. **设施与换装能力**：证明某一具体港区或货站存在，但不自动补齐时间和运价；
3. **运输服务**：证明两个设施或区域之间存在班轮、班列或短驳。只有端点、距离、时间、费用和适用日期满足模型要求时，才能成为优化器边。

因此，[`facility-network.svg`](../benchmarks/facility-network/facility-network.svg) 中的虚线表示“发现了服务证据”，不是已经完成数值校准的优化网络。

## 2. 两层地理范围

- `corridor_external`：重庆、武汉、九江等长江干线节点，负责把货物送入长三角；
- `yrd`：沪苏浙皖内部港区、铁路货站和集疏运设施。

重庆—上海走廊不能整体称为“长三角23城网络”。历史列表中既有城市，也有阳逻、高港等港区或片区名称。

## 3. 时间快照

- `historical_2022` 截止到 2022-11-20，只允许使用当时已经运营且能够由当时资料支持的设施；
- `current_reference` 截止到 2026-09-27，用于后续增强模型。

例如南通港通海集装箱码头的四川—南通—浙江铁水联运记录发生在2026年，因此只进入当前参考快照，不会写进2022网络。南京—上海天天班的公开记录晚于比赛时间，也不会反向解释成2022年已经存在的服务。

## 4. 第一批设施

当前登记20个设施或待解析港口候选，其中15个已经解析到具体港区/货站，8个进入普通集装箱核心候选：

- 重庆果园港；
- 芜湖港朱家桥港区；
- 南京港龙潭港区；
- 苏州港太仓港区；
- 上海港外高桥港区；
- 芦潮港铁路集装箱中心站；
- 上海港洋山深水港区；
- 宁波舟山港穿山港区。

“核心”只说明设施应进入下一阶段数据采集，不表示它已经与其他所有核心节点相连。

另有杨浦铁路货站和重庆团结村站两个 `evidence_only` 节点，用来准确保存2011年55–60小时历史班列的真实端点。它们不被偷换成果园港—芦潮港当前班列。

裕溪口被标记为 `cargo_specific`，因为其核心优势是煤炭铁水联运，不能仅因位于芜湖就加入普通集装箱基准图。安庆、九江、马鞍山和湖州仍缺与本案例相匹配的具体作业区或服务证据，暂不作为优化节点。

## 5. 已确认的关键服务事实

### 重庆—上海水运

- 2019年资料给出果园港至外高桥不超过192小时；
- 果园港至洋山可经外高桥或太仓之一中转，不超过240小时；
- 2022年资料给出沪渝直达快线8—9天、普通水运11—12天，并明确快线采用中途不停等组织方式。

这意味着武汉、九江、安庆不能因为位于沿江方向就被解释成这条直达快线的换装点。

### 上海港站分离

芦潮港铁路中心站与洋山港是两个设施。官方方案明确由运营主体负责两者间最后一公里短驳，因此模型必须表示为铁路卸箱/堆场—公路短驳—洋山进港，而不是一次免费的“铁路转水运”。

### 芜湖—上海

公开资料确认2020年开通芜湖—上海宜东内贸直达和芜湖—外高桥外贸直达航线，并给出“五定班轮”60小时航行承诺。但该服务资料没有解析到具体芜湖作业区，也没有完整可比运价和航道距离，所以目前保留为A级服务证据，不直接构造优化器边。

### 南京—上海

龙潭港区铁路专用线在2020年通过验收。后续资料确认南京—上海海铁联运天天班以及龙潭—洋山链路，但没有公开一组可直接用于当前成本函数的完整距离、时间、短驳费用和箱价，因此尚未数值化。

## 6. 为什么原始证据层仍是0条可直接优化的设施边

11条服务证据来自政府、运营方、行业协会或公开市场记录，但每条通常只给出以下信息的一部分：

- 服务存在；
- 起止港或大致区域；
- 最大时效或班次；
- 某一案例的节省额。

它们没有同时给出“精确设施端点、航道/铁路距离、可比全程运价、班次等待、装卸和短驳成本”。仓促把缺项补成数字会再次制造一个看似真实、实为假设的完全图。因此第一阶段明确记录为0条 `optimizer_eligible` 服务和0项 `optimizer_eligible` 换装。

这不代表没有真实运输服务，而是表示还没有达到本仓库设定的“全部字段均为设施级观测值”门槛。现有端到端走廊敏感性实验继续独立存在，并明确属于走廊级校准，不冒充设施网络。

第二阶段已另建 [`model_inputs.json`](../data/facility_network/model_inputs.json)：7条数值边、1项设施特定换装和3个可运行案例。它允许把运营方比较值、官方市场指数、单条市场观察、团队采集值和明确假设组合成分析网络，但不会反向把 `services.json` 改成“已观测完整”。重庆案例中的真实多段结构是果园港—铁路→芦潮港—公路→洋山；水运仍作为打包服务，太仓/外高桥不会被误当成自由换装点。详细数值、路线切换和剩余缺口见 [`FACILITY_NUMERIC_MODEL_CN.md`](FACILITY_NUMERIC_MODEL_CN.md)。

## 7. 后续数据补齐顺序

按对可行路线的贡献而不是按城市数量收集：

1. 重庆铁路价是否包含上海港短驳，以及芦潮港—洋山合同价和等待分布；上海端已收窄到芦潮港，处理时间已有“1小时完成率大于60%”的边界，但当前重庆始发站、班次和取消率仍未知；
2. 果园港—外高桥、果园港—太仓—洋山的航道距离、箱价口径、班期和等待时间；
3. 芜湖具体始发港区—外高桥的“五定班轮”班期、实际航程和费用范围；
4. 龙潭港—龙潭站—芦潮港/洋山各段距离、列车时刻、短驳和装卸费用；
5. 穿山港区实际铁路班列与重庆/长三角腹地的服务端点；
6. 安庆、九江是否存在与本案例货类匹配、时间截面一致的具体铁路货站和港区换装服务。

每补齐一项数据，都必须保存来源、发布日期、适用时间、单位、费用包含范围和证据等级。不能用港口吞吐量代替重庆—上海OD货量，也不能把一条首发案例描述成稳定班次。

## 8. 可复现文件

- [`sources.json`](../data/facility_network/sources.json)：来源与每份资料能证明的范围；
- [`facilities.json`](../data/facility_network/facilities.json)：设施、货类、方式、快照状态与准入决定；
- [`services.json`](../data/facility_network/services.json)：服务证据和仍缺的数值字段；
- [`transfers.json`](../data/facility_network/transfers.json)：已确认的换装能力及缺项；
- [`model_inputs.json`](../data/facility_network/model_inputs.json)：逐字段标注来源的校准边、换装和案例；
- [`operational_evidence_gaps.json`](../data/operational_evidence_gaps.json)：六类运营缺口的公开证据、剩余未知和模型处理；
- [`facility_data.py`](../routing/facility_data.py)：防止规划节点和不完整服务被误提升为优化边的验证器；
- [`facility_network.py`](../routing/facility_network.py)：把校准层转换为标准网络配置；
- [`build_facility_network.py`](../tools/build_facility_network.py)：生成CSV清单、摘要和示意图；
- [`run_facility_case_analysis.py`](../tools/run_facility_case_analysis.py)：生成1260格敏感性结果和路线可视化。

运行：

```bash
python3 -B tools/build_facility_network.py
python3 -B tools/run_facility_case_analysis.py
```

输出分别位于 [`benchmarks/facility-network`](../benchmarks/facility-network/README.md) 和 [`benchmarks/facility-case-analysis`](../benchmarks/facility-case-analysis/README.md)。
