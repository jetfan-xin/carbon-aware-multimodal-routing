# 原始 GA_code 与当前维护版比较

## 比较边界

- **原始版**：`historical/GA_code/` 中六个 2022-11-23 Python 文件的字节级快照。它是本次找回的项目特有代码，但不包含 Geatpy、原始虚拟环境或工作簿。
- **当前维护版**：Git 提交 `329d84ea50ed9b19169d410f596266c333531f12` 首次实现、基线 HEAD `2f3551f4db70f79ca39471f2226676686c1caad8` 中继续修订的代码，现保存在 `routing/`。它用于可复现验证和扩展实验，不作为 2022 原代码。
- 当前机器的“运行验证”包括未改成本函数的复算；此外，2022年的第99代终端日志、100代trace和答辩记录构成独立历史运行证据。当前平台未做到的是字节级环境复现，不是历史运行是否发生。

## 算子层面的关键事实

原始入口在 `historical/GA_code/main.py` 第22–25行创建SEGA；当前保存值为100,000个RI个体和 `MAXGEN=1`。在这一参数下只评价初始种群，但修改 `MAXGEN` 即执行完整SEGA循环。2022终端日志的第99代和100,000次评价、答辩中的100轮说明与trace证明项目确实运行过多代GA。因此当前默认值只能描述一个保存配置，不能定义算法能力或历史事实。

Geatpy框架默认算子来自第三方，不是个人实现。项目特有的问题建模、优先级解码、成本函数、算法配置以及答辩所述自适应/灾变设计属于个人项目工作。当前七文件快照未包含自定义控制器，因此精确源码版本仍需追踪。当前维护版实现了可独立消融的现代自适应和灾变机制，其公式、约束和安全解码器都清楚标为后来增强。

## 需要纠正的表述

1. “完整比赛求解器未找回”应改为：项目特有的 `GA_code` 已找回并保留；但精确历史环境、随机状态、某些日志配置和可分发工作簿仍缺失，所以完整运行不可复现。
2. “2022年设计并实现自适应GA和20代灾变”有同期答辩与运行产物支持；严谨报告需注明精确自定义控制器源码修订尚未匹配。鲁棒情景优化仍缺少可执行数据流证据。
3. “多目标优化”不准确：找回代码是四类费用求和后的单目标最小化，排放通过碳成本进入。
4. “排放约束/硬时间窗”不准确：找回代码只计算碳费用与早晚软惩罚，`CV` 始终为零。
5. “全局最优路线”不准确：原始输出是无最优性证明的启发式随机候选最优。
6. “地图由最优解自动生成”不准确：地图脚本硬编码路线，未导入求解结果。
7. 当前维护版的回溯、JSON schema、风险目标、排放上限、确定性 seed、重启公式与 exact baseline 都应标为后来新增功能。
